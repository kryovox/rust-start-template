## 1. Зачем нужен цикл

Цикл позволяет повторять действия по заданному правилу. Например, нужно вывести числа от 1 до 5, сложить несколько значений или проверять последовательные числа до нахождения подходящего. Для повторяющегося действия удобно один раз записать общее правило.

Один проход через тело цикла называется итерацией. Тело цикла — инструкции в его фигурных скобках. Если цикл выводит по одному числу и сделал пять проходов, говорят, что выполнено пять итераций.

Чтобы понимать цикл, ответьте на три вопроса: с какого состояния начинается работа; что изменяется после очередного прохода; при каком условии повторение закончится. Состояние — текущие значения переменных, которые влияют на выполнение. Например, это номер обрабатываемого числа и накопленная сумма.

В Rust используются три основные формы циклов: `loop`, `while` и `for`. Рассмотрим каждую и проследим, как программа переходит от одной итерации к следующей.

## 2. Цикл loop и выход через break

Цикл loop повторяет тело, пока выполнение не будет прервано. Внутри можно проверить нужное условие и закончить цикл с помощью `break`.

```rust
fn main() {
    let mut number: i32 = 1;
    loop {
        println!("Число: {}", number);
        if number == 3 {
            break;
        }
        number += 1;
    }
    println!("Цикл завершён.");
}
```

Сначала number равно 1. Программа выводит число, проверяет равенство трём и увеличивает number. Затем выполнение возвращается к началу тела loop. На следующем проходе обрабатывается 2, затем 3.

Когда number равно 3, выполняется break. Он завершает текущий цикл. До строки number += 1 на этом проходе выполнение уже не дойдёт. Следующая выполняемая команда расположена за циклом: она напечатает сообщение о завершении.

Ожидаемый вывод: «Число: 1», «Число: 2», «Число: 3», затем «Цикл завершён». Переменная number изменяется, поэтому в объявлении требуется mut.

Запись loop сама по себе не задаёт условия остановки. В примере завершение обеспечивает проверка number == 3. При разборе такого кода обязательно найдите действие, которое завершает повторение, и объясните, почему программа до него дойдёт.

Справка! Если при самостоятельном эксперименте программа бесконечно печатает строки или продолжает работать без завершения, остановите её сочетанием Ctrl+C в терминале. Затем проверьте условие выхода и изменение переменных.

## 3. Цикл while

У цикла while условие повторения записывается сразу после ключевого слова. Оно проверяется перед каждой итерацией. Если получается true, выполняется тело. После тела программа снова проверяет условие. При false цикл заканчивается.

Сделаем обратный отсчёт:

```rust
fn main() {
    let mut remaining: i32 = 3;
    while remaining > 0 {
        println!("Осталось: {}", remaining);
        remaining -= 1;
    }
    println!("Старт!");
}
```

Здесь remaining — количество оставшихся шагов. Перед первым проходом оно равно 3. Проверка 3 > 0 даёт true, программа печатает 3 и уменьшает значение до 2. Затем аналогично обрабатываются 2 и 1.

| Проверка по порядку | Значение remaining | Результат условия | Что происходит |
| --- | --- | --- | --- |
| 1 | 3 | true | Печатается 3, значение становится 2 |
| 2 | 2 | true | Печатается 2, значение становится 1 |
| 3 | 1 | true | Печатается 1, значение становится 0 |
| 4 | 0 | false | Цикл заканчивается |

После цикла выполняется println! с сообщением «Старт!». Проверок условия получилось четыре, выполненных итераций — три. Последняя проверка завершила повторение.

Если сразу задать remaining = 0, тело не выполнится ни разу. Программа сразу напечатает «Старт!». Это важное свойство while: условие проверяется до первого прохода.

### Почему должно изменяться состояние

В нашем отсчёте строка remaining -= 1 приближает программу к завершению. Если убрать её, remaining останется равным 3 и условие будет продолжать давать true. При чтении while найдите переменные из условия и проверьте, как они изменяются.

Направление изменения также имеет значение. При условии remaining > 0 увеличение положительного remaining не обеспечивает ожидаемый отсчёт к нулю. Начальное значение, условие и изменение должны описывать один согласованный алгоритм.

## 4. Цикл for и диапазоны

Цикл for последовательно получает значения из перебираемого источника. Один из самых простых источников — диапазон целых чисел.

```rust
fn main() {
    for number in 1..=5 {
        println!("Квадрат {} равен {}", number, number * number);
    }
}
```

Запись `for number in 1..=5` означает: по очереди брать числа от 1 до 5 включительно и на каждом проходе использовать текущее число под именем number. Получатся пять строк: квадраты 1, 4, 9, 16 и 25 для чисел 1, 2, 3, 4 и 5.

Переменную number создаёт сама конструкция for. На каждой итерации она получает очередное значение. Вручную увеличивать её для перехода к следующему числу не требуется. После обработки последнего элемента цикл заканчивается.

### Включённая и исключённая правая граница

Диапазон `a..b` включает левую границу a и заканчивается перед b. Диапазон `a..=b` включает обе границы. Эти записи нужно читать внимательно, поскольку один знак меняет набор обрабатываемых значений.

| Диапазон | Получаемые значения | Число проходов |
| --- | --- | --- |
| `1..5` | 1, 2, 3, 4 | 4 |
| `1..=5` | 1, 2, 3, 4, 5 | 5 |
| `0..3` | 0, 1, 2 | 3 |
| `5..5` | Нет значений | 0 |
| `5..=5` | 5 | 1 |

Для целочисленного диапазона с началом больше конца обычного прямого перебора не получится: он пуст. Например, 5..1 не создаёт обратный отсчёт. Когда нужно двигаться в обратном направлении, применяется специальное преобразование порядка.

Границы можно задавать переменными: `for number in 1..=limit`. Значение limit должно иметь тип, согласованный с границами диапазона. Для наших примеров подходят небольшие значения i32 или u32. Переменная самого for доступна в его теле.

Диапазон для одного запуска for создаётся при входе в цикл. Изменение переменной limit внутри тела не перестраивает уже созданный диапазон. Если условие продолжения должно заново зависеть от меняющегося значения после каждого прохода, это можно выразить через while.

### Обратный порядок и шаг

Метод `rev()` позволяет перебрать подходящий числовой диапазон в обратном порядке. Метод — операция, которую вызывают через точку у значения. В записи `(1..=3).rev()` сначала задаётся диапазон, затем к нему применяется изменение порядка.

Метод `step_by()` задаёт шаг перебора: после первого элемента берётся каждый следующий элемент через указанное количество позиций. Шаг должен быть положительным; значение 0 приведёт к ошибке выполнения.

```rust
fn main() {
    println!("Обратный отсчёт:");
    for number in (1..=3).rev() {
        println!("{}", number);
    }
    println!("Шаг два:");
    for number in (0..=6).step_by(2) {
        println!("{}", number);
    }
}
```

Первый цикл выведет 3, 2, 1. Второй выведет 0, 2, 4, 6. Скобки помогают применить метод ко всему диапазону. Шаг 2 выбирает каждый второй элемент, начиная с первого: для диапазона 1..=6 получились бы 1, 3, 5.

Параметр шага имеет тип usize — целый тип для размеров и индексов. В примере число 2 получает нужный тип из вызова step_by. Чтобы использовать эти приёмы, сейчас достаточно понимать порядок получаемых чисел; устройство итераторов подробно рассмотрим при работе с коллекциями.

## 5. Счётчик и накопитель

Счётчик хранит количество подходящих случаев. Накопитель хранит общий результат, который постепенно изменяется: например, сумму. Обычно их создают перед циклом, чтобы значение сохранялось между итерациями.

Найдём количество и сумму чётных чисел от 1 до 6 включительно:

```rust
fn main() {
    let mut count: u32 = 0;
    let mut total: u32 = 0;
    for number in 1..=6 {
        if number % 2 == 0 {
            count += 1;
            total += number;
        }
    }
    println!("Количество: {}", count);
    println!("Сумма: {}", total);
}
```

Подходят числа 2, 4 и 6. После их обработки count равно 3, total равно 12. Увеличение count на единицу учитывает найденное число, а прибавление number к total учитывает его величину.

| Обработанное число | Подходит условию | count после прохода | total после прохода |
| --- | --- | --- | --- |
| 1 | Нет | 0 | 0 |
| 2 | Да | 1 | 2 |
| 3 | Нет | 1 | 2 |
| 4 | Да | 2 | 6 |
| 5 | Нет | 2 | 6 |
| 6 | Да | 3 | 12 |

Начальное значение суммы равно нулю: до начала перебора ни одно число ещё не добавлено. После каждого прохода total соответствует сумме всех уже обработанных подходящих чисел. Эта связь между переменной и обработанной частью задачи помогает проверять алгоритм.

Если создать total заново внутри тела цикла со значением 0, накопление будет начинаться сначала на каждом проходе. Поэтому переменные общего результата находятся перед циклом. Локальные промежуточные значения, нужные одному проходу, удобно создавать внутри него.

## 6. Пропуск итерации и досрочное завершение

Команда continue завершает текущую итерацию и переходит к следующей. У for при этом получается очередное значение перебора. У while выполнение переходит к очередной проверке условия.

```rust
fn main() {
    for number in 1..=5 {
        if number == 3 {
            continue;
        }
        println!("{}", number);
    }
    println!("Перебор завершён.");
}
```

Будут напечатаны 1, 2, 4 и 5, затем сообщение о завершении. На проходе с number = 3 выполняется continue, поэтому до println! внутри тела программа не доходит. Следующий проход получает number = 4.

В while следите, чтобы continue не обходил изменение счётчика, необходимое для продвижения. Если увеличение стоит ниже continue, при некоторых значениях программа может постоянно возвращаться к той же проверке. Перед добавлением пропуска проследите следующий проход вручную.

Команда break завершает текущий цикл целиком. Например, найдём первое число от 1 до 10, которое делится на 7:

```rust
fn main() {
    for number in 1..=10 {
        if number % 7 == 0 {
            println!("Найдено: {}", number);
            break;
        }
    }
    println!("Поиск завершён.");
}
```

Числа 1–6 не подходят. На числе 7 появляется сообщение «Найдено: 7», выполняется break, затем печатается «Поиск завершён». Числа 8, 9 и 10 уже не обрабатываются.

### Значение из loop

Цикл loop может дать значение выражению. Для этого в момент выхода после break указывается результат:

```rust
fn main() {
    let mut number: i32 = 1;
    let found = loop {
        if number % 7 == 0 {
            break number;
        }
        number += 1;
    };
    println!("Результат поиска: {}", found);
}
```

При достижении числа 7 запись `break number` завершает loop и передаёт 7 как значение всего выражения loop. Оно сохраняется в found. После закрывающей скобки стоит точка с запятой, завершающая инструкцию let.

Такой способ передачи значения после break в рассматриваемых конструкциях используется с loop. В обычных while и for мы сохраняем результат во внешней переменной либо, как увидим дальше, возвращаем его из функции.

## 7. Вложенные циклы

Один цикл может находиться внутри другого. Тогда для каждого прохода внешнего цикла внутренний проходит свой набор значений заново. Например, выведем номера мест в двух рядах по три места:

```rust
fn main() {
    for row in 1..=2 {
        for seat in 1..=3 {
            println!("Ряд {}, место {}", row, seat);
        }
    }
}
```

Сначала row равно 1, а seat последовательно получает 1, 2 и 3. Затем row становится равным 2, и перебор seat снова начинается с 1. Получатся шесть пар: (1, 1), (1, 2), (1, 3), (2, 1), (2, 2), (2, 3).

Общее число выполнений println! равно 2 × 3 = 6. Если количество рядов и мест существенно увеличивается, число действий растёт как их произведение. Это стоит учитывать при оценке работы вложенных циклов.

Обычные break и continue относятся к ближайшему окружающему циклу. Поэтому break внутри перебора seat завершит перебор мест текущего ряда. Внешний перебор row после этого сможет продолжиться. Более сложное управление несколькими уровнями оставим для отдельных задач.

## 8. Что такое функция

Функция — именованная часть программы, которую можно вызвать для выполнения определённой работы. Она может получать исходные данные через параметры и передавать результат вызывающему коду. Например, одна функция проверяет чётность числа, другая находит сумму, третья выводит сообщение.

Вы уже использовали главную функцию main. Теперь создадим собственную. Для объявления применяется ключевое слово `fn`, после него записываются имя, круглые скобки и тело в фигурных скобках.

```rust
fn print_greeting() {
    println!("Добро пожаловать в программу!");
}

fn main() {
    print_greeting();
    print_greeting();
}
```

Вызов `print_greeting()` передаёт выполнение в тело функции. Там печатается приветствие. После окончания тела работа продолжается со следующей инструкции в main. В примере приветствие появится дважды, поскольку вызов записан два раза.

Объявление функции описывает её работу. Само по себе присутствие объявления в файле не вызывает эту работу. Для выполнения нужен вызов. Круглые скобки в print_greeting() обозначают вызов без аргументов.

Имена функций в Rust принято записывать маленькими латинскими буквами, разделяя слова подчёркиваниями: print_greeting, sum_to, is_even. Имя должно помогать понять задачу функции.

Наши функции располагаются на одном уровне с main. Их можно объявлять до main или после неё: Rust допускает вызов доступной функции независимо от её положения выше или ниже в этом файле. Порядок реального выполнения задают вызовы и инструкции внутри тел.

### Функция, которая выполняет действие

Функция print_greeting печатает сообщение. У неё не указан отдельный тип результата после круглых скобок. В этой записи возвращается значение специального типа `()`, который называют unit. Его удобно понимать как отсутствие содержательного вычислительного результата.

Сообщение на экране и возвращаемое значение — разные части поведения функции. Для дальнейшего вычисления суммы нам потребуется функция с числовым результатом. Для вывода сообщения подходит функция, выполняющая действие и завершающаяся с unit.

## 9. Параметры и аргументы

Параметры — локальные имена для данных, с которыми работает функция. Они объявляются в круглых скобках после имени. Для каждого параметра указывается тип. Аргументы — конкретные значения, переданные при вызове.

```rust
fn print_cost(price: i32, quantity: i32) {
    let total = price * quantity;
    println!("Стоимость: {} руб.", total);
}

fn main() {
    print_cost(250, 3);
    print_cost(100, 4);
}
```

В объявлении print_cost параметры — price и quantity. В первом вызове аргументы — 250 и 3. При его выполнении price получает 250, quantity получает 3, а total становится равным 750. Во втором вызове параметры получают 100 и 4, результат вычисления total равен 400.

Значения передаются по порядку: первый аргумент соответствует первому параметру, второй — второму. Имена переменных у вызывающего кода могут быть другими. Например, вызов `print_cost(ticket_price, ticket_count)` передаст значения ticket_price и ticket_count на соответствующие позиции.

Типы аргументов должны подходить к типам параметров. В этой функции ожидаются два значения i32. При объявлении нужно написать `price: i32, quantity: i32`: тип указан у каждого параметра отдельно.

Аргументом может быть выражение. Вызов `print_cost(100 + 50, 2)` сначала вычислит 100 + 50, затем передаст 150 и 2. Вызов функции — ещё один способ использовать результаты выражений.

При каждом вызове создаются свои локальные параметры и переменные. Значение total из первого вызова не остаётся накопленной суммой для второго. Если функция должна учитывать предыдущий результат, соответствующие данные нужно передать явно и определить нужное правило вычисления.

## 10. Возвращаемое значение

Чтобы результат можно было сохранить или использовать дальше, укажем тип после стрелки `->`. В конце тела запишем выражение, значение которого должна вернуть функция.

```rust
fn add(left: i32, right: i32) -> i32 {
    left + right
}

fn main() {
    let result = add(2, 3);
    println!("Сумма: {}", result);
    println!("Другой вызов: {}", add(10, 5 * 2));
}
```

Стрелка -> i32 сообщает, что вызов add даёт целое число i32. Выражение left + right в конце тела становится результатом функции. Первый вызов даёт 5. Во втором сначала вычисляется аргумент 5 * 2 = 10, затем add складывает 10 и 10 и возвращает 20.

Возвращённое значение в первом случае сохраняется в result, во втором сразу передаётся в println!. Его можно использовать и в условии, и в другом вычислении, если тип подходит.

### Последнее выражение и точка с запятой

В строке left + right точки с запятой нет. Эта запись даёт результат тела функции. Если написать `left + right;`, значение будет вычислено и отброшено, а завершение такого блока даст unit. Объявленный результат i32 с этим не согласуется, поэтому компилятор сообщит об ошибке.

Такая же идея уже встречалась в выражениях if и match. Последним выражением функции может быть и целая условная конструкция:

```rust
fn ticket_price(has_benefit: bool) -> i32 {
    if has_benefit {
        250
    } else {
        400
    }
}

fn main() {
    let price = ticket_price(true);
    println!("Цена: {} руб.", price);
}
```

Для true выбранная ветвь даёт 250. Это значение становится результатом if, затем результатом всей функции. Для false функция вернёт 400. В обеих ветвях получается i32. После последнего if в этой функции точка с запятой тоже отсутствует.

### Ранний выход через return

Команда `return` завершает текущую функцию и передаёт указанный результат вызывающему коду. Это позволяет обработать особый случай в начале вычисления.

Условие следующего примера: определить, можно ли раздать total предметов поровну people участникам без остатка. Для people = 0 договоримся возвращать false.

```rust
fn can_share_evenly(total: u32, people: u32) -> bool {
    if people == 0 {
        return false;
    }
    total % people == 0
}

fn main() {
    println!("21 на 3: {}", can_share_evenly(21, 3));
    println!("21 на 0: {}", can_share_evenly(21, 0));
}
```

Для первого вызова people равно 3, ранний выход пропускается, проверяется остаток 21 % 3 и возвращается true. Для второго people равно 0: return false завершает функцию до операции %. Деление или остаток от деления на ноль в этом случае не выполняется.

В строке return false; точка с запятой есть: это инструкция явного выхода. Работа после вызова продолжается в main. Поэтому ранний return из вспомогательной функции не мешает программе выполнять следующие команды main.

Функция с результатом должна выдавать значение подходящего типа на каждом пути нормального завершения. Проследите все ветви: какой результат получится при обычном вводе и при особом случае. В примере оба пути возвращают bool.

## 11. Область видимости и локальные значения

Область видимости определяет, где можно обратиться к имени. Параметры доступны внутри своей функции. Переменная, объявленная в блоке, доступна после объявления внутри этого блока и его вложенных блоков.

Например, total, созданная внутри print_cost, используется в теле print_cost. Функция main не получает доступ к ней по одному имени total. Если main нужен вычисленный результат, его следует вернуть из функции и сохранить у вызывающего кода.

Обычная функция, объявленная рядом с main, также не получает автоматически доступ к локальным переменным main. Нужное значение передаётся аргументом. Это делает входные данные функции явными.

### Что происходит с числовым параметром

В наших примерах i32, u32 и bool копируются при передаче по значению. Изменение локального числового параметра относится к его локальному связыванию. Проследим это на примере:

```rust
fn add_bonus(mut score: i32) -> i32 {
    score += 10;
    score
}

fn main() {
    let score: i32 = 50;
    let updated = add_bonus(score);
    println!("Исходное значение: {}", score);
    println!("С бонусом: {}", updated);
}
```

Внутри функции параметр score получает 50. Слово mut разрешает изменить его до 60. Затем 60 возвращается и сохраняется в updated. Вывод покажет исходное значение 50 и результат с бонусом 60.

Если нужно сохранить результат под прежним именем у вызывающего кода, там можно объявить переменную изменяемой и выполнить `score = add_bonus(score);`. Правила передачи строк и других составных значений потребуют отдельного изучения владения и заимствования; сейчас рассматриваем указанные простые копируемые типы.

### Как различать break, continue и return

| Запись | Что заканчивается | Где продолжится работа |
| --- | --- | --- |
| `continue;` | Текущая итерация ближайшего цикла | Следующий проход либо проверка условия |
| `break;` | Ближайший цикл | После этого цикла |
| `return value;` | Текущая функция | В вызывающем коде с полученным результатом |

Если return находится внутри цикла функции, он завершает функцию целиком. Это бывает удобно для поиска: найденный ответ можно сразу вернуть. Команда break позволяет закончить цикл и выполнить дальнейшие инструкции той же функции.

## 12. Функции с циклами

Цикл может находиться внутри функции. Параметры задают исходные данные, локальные переменные хранят промежуточное состояние, а возвращаемое значение содержит итог.

### Сумма от 1 до заданной границы

Определим правило: sum_to получает неотрицательный limit типа u32 и возвращает сумму всех положительных целых чисел от 1 до limit включительно. Для limit = 0 подходящих чисел нет, поэтому сумма равна нулю.

```rust
fn sum_to(limit: u32) -> u64 {
    let mut total: u64 = 0;
    for number in 1..=limit {
        total += number as u64;
    }
    total
}

fn main() {
    println!("Сумма до 5: {}", sum_to(5));
    println!("Сумма до 0: {}", sum_to(0));
}
```

Для limit = 5 накапливаются 1, 2, 3, 4 и 5, получается 15. Для limit = 0 диапазон 1..=0 пуст и total остаётся равным 0. Нулевая граница обрабатывается самим правилом перебора.

Для суммы выбран u64, чтобы предоставить больший диапазон результата. Значение number имеет тип u32, поэтому при сложении явно преобразуется в u64 через as. Параметр и результат функции могут иметь разные типы, если переход между ними предусмотрен вычислением.

В учебных запусках используйте небольшие границы, например до 10 000. Функция выполняет отдельную итерацию для каждого числа. При увеличении limit увеличивается и число действий. Формула суммы тоже существует, а здесь нам важно проследить алгоритм накопления.

### Сумма цифр через while

Для целого неотрицательного числа операция % 10 даёт последнюю десятичную цифру, а целое деление на 10 удаляет её из оставшейся записи числа. Например, у 123 остаток от деления на 10 равен 3, а результат деления равен 12.

```rust
fn digit_sum(mut number: u32) -> u32 {
    let mut total: u32 = 0;
    while number > 0 {
        total += number % 10;
        number /= 10;
    }
    total
}

fn main() {
    println!("Сумма цифр 123: {}", digit_sum(123));
    println!("Сумма цифр 0: {}", digit_sum(0));
}
```

Для 123 функция сначала добавляет 3 и оставляет number = 12. Затем добавляет 2 и оставляет 1. После добавления 1 остаётся 0, цикл завершается. Итог равен 6.

Для исходного числа 0 тело while не выполняется. Переменная total сохраняет 0, что соответствует сумме цифр числа 0. Ключевое слово `mut` перед number нужно, потому что локальный параметр последовательно уменьшается при делении на 10.

Обе функции выполняют вычисление и возвращают число. Их main выводит понятное пользователю сообщение. Благодаря возвращаемому значению результат можно использовать и для дальнейших действий: например, проверить `digit_sum(123) > 5` в условии.

### Описание правила функции

Перед написанием полезно кратко сформулировать контракт функции: какие данные она получает, что возвращает и как обрабатывает граничные случаи. Это обычное объяснение смысла функции, которое помогает вызывающему коду и тестам опираться на одно правило.

Для digit_sum вход — любое значение u32, результат — сумма его десятичных цифр, для 0 возвращается 0. Для can_share_evenly отдельно оговорён случай people = 0. Такие уточнения позволяют проверять конкретное поведение и обнаруживать пропущенные случаи.

## 13. Простые проверки результата

Проверка по выводу помогает увидеть работу программы. Автоматическая проверка позволяет прямо в коде зафиксировать ожидаемый результат и получить сообщение, если он нарушен. Это особенно удобно для функций с возвращаемым значением.

Проверка обычно состоит из трёх действий: подготовить исходные данные, вызвать функцию, сравнить результат с известным ожидаемым значением. Например, для add(2, 3) мы заранее знаем ответ 5.

Макрос `assert_eq!()` проверяет равенство двух значений. В наших примерах первым указываем фактический результат, вторым — ожидаемый. Макрос `assert!()` проверяет, что логическое выражение даёт true.

```rust
fn add(left: i32, right: i32) -> i32 {
    left + right
}

fn main() {
    assert_eq!(add(2, 3), 5);
    assert_eq!(add(0, 0), 0);
    assert!(add(2, 3) > 0);
    println!("Все проверки пройдены.");
}
```

Все утверждения выполняются, поэтому появится сообщение «Все проверки пройдены». Успешные assert! и assert_eq! сами по себе ничего не печатают. Если утверждение нарушено, возникает panic — сообщение об ошибке выполнения, которое в такой обычной программе прерывает текущую работу.

Для знакомства с ошибкой временно замените ожидаемое значение 5 в первой проверке на 6. Вызов add(2, 3) по-прежнему даст 5. Проверка завершится ошибкой сравнения и покажет различающиеся значения. После наблюдения верните ожидаемый ответ 5.

Числа для теста нужно брать из понятного правила или самостоятельного ручного расчёта. Если ожидаемый ответ вычисляется той же ошибочной формулой, что и проверяемая функция, проверка может пропустить ошибку. Для маленьких примеров полезно сначала записывать ответ самостоятельно.

## 14. Тестовые функции и cargo test

Rust умеет находить и запускать специально помеченные тестовые функции. Над такой функцией ставят атрибут `#[test]`. Атрибут — служебная пометка для компилятора и инструментов языка.

Разместим вычислительную функцию, обычный main и тесты в одном файле src/main.rs:

```rust
fn add(left: i32, right: i32) -> i32 {
    left + right
}

fn main() {
    println!("Сумма: {}", add(2, 3));
}

#[cfg(test)]
mod tests {
    use super::add;

    #[test]
    fn adds_positive_numbers() {
        assert_eq!(add(2, 3), 5);
    }

    #[test]
    fn adds_zero() {
        assert_eq!(add(7, 0), 7);
    }
}
```

Команда `cargo run` выполнит main и выведет «Сумма: 5». Команда `cargo test`, запущенная в папке того же проекта, соберёт тестовый запуск и выполнит две функции с #[test]. В отчёте должны появиться два успешных теста: 2 passed и 0 failed.

Разберём новые записи. `mod tests` создаёт модуль — группу кода с собственным пространством имён. Внутри него находятся функции проверок. Пометка `#[cfg(test)]` включает этот модуль при сборке для тестирования.

Запись `use super::add;` делает функцию add из окружающего модуля доступной в тестах под именем add. Здесь super означает переход к родительскому модулю. Для сегодняшней работы достаточно понимать назначение этой строки и расположение тестов в модуле.

Каждая функция с #[test] описывает отдельный проверяемый случай. Обычный тест из нашего примера вызывается без аргументов и завершается с unit. Внутри он вызывает add и использует assert_eq!. Среда тестирования сообщает, какая проверка прошла, а какая завершилась ошибкой.

### Как читать отчёт

Сначала проверьте, собралась ли программа. Если компилятор обнаружил ошибку типов или синтаксиса, тестовые функции ещё не выполнялись. После успешной сборки смотрите названия проверок и итоговое количество passed и failed.

Если assert_eq! не выполнен внутри теста, соответствующий тест отмечается как failed. В отчёте можно найти имя теста, строку проверки и сравнивавшиеся значения. Сопоставьте их с контрактом функции и исходными данными.

Для запуска проверки с определённым именем можно выполнить `cargo test adds_positive_numbers`. Указанная часть имени служит фильтром, поэтому совпасть могут несколько имён. Команда cargo test без фильтра запускает весь доступный набор тестов проекта.

Тесты должны быть независимыми. Каждый подготавливает собственные данные и проверяет свой результат. Порядок их выполнения не является частью контракта. Примеры с локальными числами и чистым вычислением удобно проверять таким способом.

Успешный запуск подтверждает совпадение результата с ожиданием для проверенных случаев. Чтобы проверить границу диапазона или особую ветвь, нужно включить соответствующие данные в набор тестов.

### Какие случаи выбирать

Для функции sum_to полезны граница 0, минимальная положительная граница 1 и обычное значение 5. Для digit_sum — число 0, однозначное число, число с несколькими цифрами и число с нулями внутри.

| Функция и аргумент | Ожидаемый результат | Что проверяется |
| --- | --- | --- |
| `sum_to(0)` | 0 | Пустой набор положительных чисел |
| `sum_to(1)` | 1 | Включение единственного числа |
| `sum_to(5)` | 15 | Обычное накопление суммы |
| `digit_sum(0)` | 0 | Случай без проходов while |
| `digit_sum(7)` | 7 | Одна цифра |
| `digit_sum(1002)` | 3 | Нули внутри числа |

После изменения функции запускайте тесты снова. Например, замена 1..=limit на 1..limit меняет включение правой границы. Проверки с limit = 1 и limit = 5 помогают сразу заметить такой сдвиг.

## 15. Общая работа «Анализ диапазона чисел»

Соберём программу, которая находит количество и сумму чётных положительных чисел от 1 до заданной границы включительно. Для границы 10 это числа 2, 4, 6, 8 и 10: количество 5, сумма 30.

Программу разделим на три функции. Функция is_even отвечает на вопрос о чётности, count_even_to считает подходящие числа, sum_even_to накапливает их сумму. Функция main задаёт границу и показывает пользователю результат.

| Функция | Входные данные | Результат |
| --- | --- | --- |
| `is_even` | number типа u32 | bool: делится ли число на 2 |
| `count_even_to` | limit типа u32 | u32: количество чётных чисел от 1 до limit |
| `sum_even_to` | limit типа u32 | u64: сумма чётных чисел от 1 до limit |

Для limit = 0 количество и сумма равны 0. Само число 0 является чётным: is_even(0) даёт true. В вычислениях по диапазону перебор начинается с 1, поэтому при нулевой границе подходящих элементов нет. Эти правила нужно учитывать отдельно в тестах.

Ниже приведены три части одного файла. Очистите src/main.rs и вставьте их последовательно: сначала функции вычисления, затем main, затем модуль тестов. В первой и третьей частях собственной функции main нет. Итоговый файл содержит одну main.

### Часть 1. Вычислительные функции

```rust,project_functions
fn is_even(number: u32) -> bool {
    number % 2 == 0
}

fn count_even_to(limit: u32) -> u32 {
    let mut count: u32 = 0;
    for number in 1..=limit {
        if is_even(number) {
            count += 1;
        }
    }
    count
}

fn sum_even_to(limit: u32) -> u64 {
    let mut total: u64 = 0;
    for number in 1..=limit {
        if is_even(number) {
            total += number as u64;
        }
    }
    total
}
```

В условии if используется результат is_even(number). У вызова тип bool, поэтому он подходит для условия. Одинаковое правило чётности определено в одной функции и используется при подсчёте и при суммировании.

В count_even_to счётчик растёт на единицу. В sum_even_to к накопителю прибавляется само подходящее число. Перед сложением оно преобразуется в u64, согласованный с типом total и типом возвращаемой суммы.

### Часть 2. Вызовы и сообщения пользователю

```rust,project_main
fn main() {
    let limit: u32 = 10;
    println!("Верхняя граница: {}", limit);
    println!("Количество чётных: {}", count_even_to(limit));
    println!("Сумма чётных: {}", sum_even_to(limit));
}
```

В этом фрагменте main вызывает уже объявленные функции. Каждая получает одно и то же значение limit. Результаты вызовов сразу передаются в println!. После cargo run ожидаются строки с верхней границей 10, количеством чётных 5 и суммой чётных 30.

Вывод описывает, что вычислено. Сами функции count_even_to и sum_even_to возвращают значения. Поэтому эти же вычисления можно проверить автоматически без чтения текста с экрана.

### Часть 3. Автоматические тесты

```rust,project_tests
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn checks_parity() {
        assert!(is_even(0));
        assert!(!is_even(3));
    }

    #[test]
    fn handles_small_limits() {
        assert_eq!(count_even_to(0), 0);
        assert_eq!(sum_even_to(0), 0);
        assert_eq!(sum_even_to(1), 0);
    }

    #[test]
    fn includes_upper_boundary() {
        assert_eq!(count_even_to(10), 5);
        assert_eq!(sum_even_to(10), 30);
    }
}
```

Запись `use super::*;` делает имена из окружающего модуля доступными внутри tests; * означает все доступные здесь имена. В этом учебном файле так подключаются наши вычислительные функции.

Первая проверка фиксирует чётность нуля и нечётность тройки. Вторая проверяет нулевую и минимальную положительную границы. Третья проверяет количество и сумму для диапазона с чётной верхней границей.

Выполните cargo test. Должны пройти три тестовые функции. Внутри них находятся несколько утверждений, однако отчёт считает тестовые функции: 3 passed означает три успешно завершённых теста.

### Самостоятельное дополнение

Добавьте тест для limit = 7. Подходят 2, 4 и 6: количество равно 3, сумма — 12. Назовите тест так, чтобы было понятно, какой случай он проверяет, например handles_odd_limit.

Затем добавьте тест для limit = 2: количество 1, сумма 2. Он проверит минимальную границу, при которой появляется первое подходящее положительное число. Запустите весь набор cargo test после добавления обеих функций. Теперь в модуле будет пять тестовых функций.

Временно измените в sum_even_to диапазон на 1..limit и запустите проверки. Тест с границей 10 должен обнаружить потерю числа 10: сумма станет 20. После наблюдения восстановите 1..=limit и убедитесь, что набор снова проходит. Это упражнение помогает увидеть связь между конкретной ошибкой и проверкой, которая её находит.

## 16. Задания для закрепления

Сначала сформулируйте вход, результат и граничные случаи каждой функции. Затем напишите код и тесты. Используйте небольшие исходные числа, чтобы ожидаемый ответ можно было проверить вручную.

### Сумма нечётных чисел

Создайте `sum_odd_to(limit: u32) -> u64`. Функция должна возвращать сумму нечётных положительных чисел от 1 до limit включительно. Для limit = 0 возвращается 0. Используйте for, диапазон и условие; результат возвращайте вызывающему коду.

Проверьте случаи 0 → 0, 1 → 1, 5 → 9 и 10 → 25. Напишите по ним автоматические проверки. В main выведите результат с понятной подписью. Поясните, какие данные хранятся в параметре, переменной цикла и накопителе.

### Количество цифр

Создайте `digit_count(number: u32) -> u32`. Функция должна возвращать количество десятичных цифр числа. По условию digit_count(0) равно 1: запись числа 0 содержит одну цифру.

Для положительного числа последовательно делите локальную изменяемую копию на 10 и считайте проходы while. Нулевой случай можно обработать ранним return. Проверьте 0 → 1, 7 → 1, 10 → 2 и 1000 → 4. Подготовьте тест, который обнаружит пропуск обработки нуля.

### Дополнительное задание

Создайте `first_multiple(start: u32, end: u32, divisor: u32) -> u32`. Для этой учебной задачи заранее заданы условия: start >= 1, start <= end, divisor >= 1, внутри включённого диапазона существует хотя бы одно подходящее число. Нужно вернуть первое число диапазона, которое делится на divisor.

Используйте for и ранний return внутри найденного случая. Чтобы оформить результат и за пределами тела for, добавьте в конце функции return 0 или последнее выражение 0. В рамках заданных условий выполнение до этого результата не дойдёт; это условный запасной результат для структуры функции. Зафиксируйте такое соглашение в описании.

Примеры: (3, 10, 4) → 4; (8, 12, 4) → 8; (9, 12, 4) → 12. Последний случай проверяет включение правой границы. В дальнейшем способ сообщать об отсутствии результата удобно будет изучить через Option; здесь работаем с заранее указанными условиями задачи.

## 17. Итоги и вопросы для самопроверки

Теперь вы можете описывать повторение, выделять вычисления в функции и фиксировать ожидаемые результаты в тестах. Циклы задают повторяющиеся шаги, функции дают им имя и явные входные данные, возвращаемые значения связывают вычисления с остальной программой.

- Что называется итерацией? Какая переменная или правило приближает ваш цикл к завершению?
- Какие значения дают 2..5 и 2..=5? Сколько проходов получится для 5..5 и 5..=5?
- Где продолжится выполнение после continue, break и return?
- Чем параметр отличается от аргумента? Что означает тип после ->?
- Почему последнее выражение функции с числовым результатом часто записано без точки с запятой?
- Что возвращает функция с выводом сообщения и без указанного типа результата?
- Что проверяют assert! и assert_eq!? Какие данные нужны для проверки границ?
- Почему успешный отчёт может содержать три теста, хотя утверждений внутри них больше?

В качестве домашней работы завершите функции sum_odd_to и digit_count с тестами, если они остались недописанными. Подготовьте файл main.rs, в котором есть вычислительные функции, пример вывода и тестовый модуль. Для сдачи проверьте обе команды: cargo run и cargo test. Дополнительное задание first_multiple выполняется при готовности основных функций.
